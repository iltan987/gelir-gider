# Implementation Plan: Windows Build, Turkish NSIS Installer & Update Checker

**Date**: 2026-03-22 | **Spec**: [spec.md](spec.md)
**Input**: Add Windows build via GitHub Actions, Turkish NSIS installer, and manual update checking in settings.

## Summary

Three additions to the existing financial tracker:

1. **GitHub Actions CI/CD** - A workflow that builds the Windows NSIS installer on `windows-latest` runners, triggered on push to a release branch or manual dispatch. Uses `tauri-apps/tauri-action@v0` to produce a signed `.exe` setup file and upload it to a GitHub Release.
2. **Turkish NSIS Installer** - The Windows installer uses Turkish as the default language. NSIS is configured with `"languages": ["Turkish"]` in `tauri.conf.json`. Custom `.nsh` translation file provides Turkish text for Tauri-specific installer messages.
3. **Manual Update Checker** - A new card in the Settings view lets the user manually check for updates. Uses `tauri-plugin-updater` to query the GitHub Releases endpoint (`latest.json`), shows version info if available, and offers download + install with progress feedback. No automatic update checking.

## Technical Context

**Language/Version**: TypeScript 5.8+ (strict) / React 19 / Rust (Tauri 2 - plugin registration only)
**Primary Dependencies**: Tauri 2, `tauri-plugin-updater`, `@tauri-apps/plugin-updater`, `tauri-apps/tauri-action@v0`
**Storage**: SQLite via `tauri-plugin-sql` (unchanged)
**Testing**: Manual testing per constitution
**Target Platform**: Windows x86_64 (NSIS installer), development on Linux (cross-build via GitHub Actions)
**Project Type**: Desktop application (Tauri 2 + React)
**Performance Goals**: Update check < 5s on broadband, installer < 30s on SSD
**Constraints**: Offline-capable (update check is user-initiated, failure is non-blocking), Turkish locale throughout
**Scale/Scope**: Single-user desktop app, 1 new settings card, 1 new service file, 1 GitHub Actions workflow
